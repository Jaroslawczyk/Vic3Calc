# Устройство программы

**[English version — ARCHITECTURE.md](ARCHITECTURE.md)**

## Единственное ограничение, определившее всё

Программа должна запускаться двойным щелчком по значку: без установщика, без
Node, без консоли, без интернета. Значит, она грузится по `file://`, а ES-модули
браузеры по `file://` не грузят.

Отсюда: **обычные `<script>`, без сборки и без зависимостей.** Всё висит на
одном глобальном объекте `V3`. Файлы данных — это `.js`, которые сами себя
регистрируют, а не `.json`, для которого понадобился бы `fetch()` (тоже
заблокирован по `file://`).

Все остальные решения вытекают из этого одного.

## Слои

```
core/     вообще не знает про игру — реестр, переводы, хранение, иконки
data/     знает про игру, но без логики — только таблицы
engine/   логика без DOM — чистые функции, первый аргумент всегда контекст
ui/       DOM без логики — читает состояние, рисует, зовёт движок
```

Слой может пользоваться только теми, что выше. `engine/` никогда не трогает
`document` — именно поэтому `tools/selftest.js` может прогнать всё это в Node.

## Порядок загрузки

`app/index.html` перечисляет все файлы в нужном порядке, по группам и с
пояснениями. Правила:

1. `core/ns.js` первым — он создаёт `V3`, `V3.views` и шину событий.
2. `core/registry.js` до любого файла из `data/` — они зовут `V3.define.*`.
3. `data/_meta.js` и `data/_helpers.js` до таблиц, которые их используют.
4. `lang/en.js` до остальных языков — английский является запасным вариантом.
5. `ui/app.js` последним — он запускает программу.

Добавить файл = добавить одну строку `<script>` и, если это файл данных, одну
строку в `tools/selftest.js`.

## Слой данных в одном абзаце

Два слоя друг на друге: **base** (`app/data/*.js`, поставляется, не изменяется)
и **user** (`localStorage`, ваши правки). `V3.db.*` всегда возвращает
объединённый результат, поэтому ничто в программе не отличает ваниль от мода.
Пользовательский слой сериализуется в один `.v3pack.json`. Списки кэшируются, а
кэш сбрасывается при любой записи: решатель запрашивает один и тот же список
тысячи раз за пересчёт, и пересортировка 226 методов производства каждый раз
была разницей между «мгновенно» и «заметно подвисает».

## Цикл обновления

```
пользователь что-то меняет
  -> V3.app.patch(fn)          меняем state.chain
  -> V3.app.recalc()           на следующем кадре анимации
       -> V3.Solver.solve()    итерация до неподвижной точки
       -> V3.Economy / Construction
  -> bus.emit('solved')
  -> открытый вид перерисовывает то, что зависит от решения
```

Виды не общаются друг с другом. Они читают `V3.app.state` и слушают `V3.bus`.
Поэтому новый экран — это ~150 строк, и он не может сломать остальные.

## Где что менять

| Что нужно | Где править |
|---|---|
| Исправить игровое число для всех | `app/data/*.js` |
| Исправить только для себя | вкладка «Данные» в программе |
| Изменить способ расчёта | `app/engine/*.js` **и** текст в `app/engine/formulas.js` |
| Изменить внешний вид | `app/styles/` — цвета только в `01-tokens.css` |
| Добавить экран | файл в `app/ui/`, одна строка `<script>`, одна запись в массиве `TABS` в `ui/app.js` |
| Добавить язык | `app/lang/` — см. [TRANSLATING.ru.md](TRANSLATING.ru.md) |
| Добавить *вид* данных | одна запись в `KINDS` в `core/registry.js` |

## Тестирование

```bash
node tools/selftest.js
```

Грузит core + data + engine в песочнице Node с заглушкой вместо браузера, затем:
проверяет все перекрёстные ссылки, правила выработки и занятости, решает девять
настоящих цепочек в правильных эрах технологий, проверяет, что порядок
строительства заканчивается тем, что вы заказали, и прогоняет экономику,
военное дело и исследования. 51 проверка. Код выхода 0 — всё в порядке.

Запускайте после *любой* правки в `app/data/` или `app/engine/`.

## Чего здесь намеренно нет

- **Никакого фреймворка.** `ui/dom.js` — это функция `h()` на 60 строк. Хватает.
- **Никакой сборки и минификации.** Тот, кто скачал программу, должен иметь
  возможность открыть любой файл и прочитать его.
- **Никакого сервера.** `tools/devserver.js` существует только ради удобных
  инструментов разработчика; самой программе он не нужен.
